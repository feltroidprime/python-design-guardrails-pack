# Pattern admission record

Before you introduce a non-trivial pattern, copy all six headings below into
an ADR. An ADR that drops a heading is not complete.

## Force

What concrete variation, boundary, lifecycle, state transition, or migration problem exists now?

## Simplest rejected design

Name the simplest function design, or module design, that you rejected. State
why it is insufficient.

## Selected pattern

Name the pattern and the exact seam it creates.

## Dependency effect

Which layer owns the abstraction? Which layer implements it? Show the new import direction.

## Cost

Additional concepts, files, runtime indirection, test burden, operational risk, and onboarding cost.

## Removal or revisit trigger

Name the future evidence that shows this abstraction is unnecessary or needs redesign.
